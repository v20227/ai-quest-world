# V0.1 SCOPE — AI Quest World

## 1. Scope statement

v0.1 is a **local, read-only, Web-rendered vertical slice** proving that real Agent Harness runtime activity can become persistent game progression without requiring an extra AI model.

The version succeeds by proving the real-work loop and the bounded local economy and companion loop below, not by shipping a large RPG. Read-only applies to the connected Harness; player actions may mutate local game state.

### Accepted economy and companion extension

- Earn local Gold from qualifying real Quest outcomes under an explicit bounded reward policy.
- View wallet balance, income and spending history.
- Buy fixed-price items with Gold; persist payment and delivery atomically.
- Maintain a unified catalog and inventory for cosmetics, pet eggs and food, separate from real artifact references.
- Hatch owned eggs into pets and feed owned food to increase persistent pet growth.
- Select a pet to display in the world, without combat stats or Harness control.
- Support restart recovery and idempotent player commands, including concurrent browser requests.
- Initial defaults: fixed-price purchases, explicit egg-to-species mapping, no hunger penalties, pet death, mandatory daily feeding, real-money payments or player trading. GAME_RULES.md defines the economy-1 grants, prices, historical backfill, single initial species and growth stages.

## 2. Must-have capabilities

### Harness/runtime

- one adapter contract
- one contract-faithful mock/simulated adapter for deterministic tests
- one first real harness adapter by the end of v0.1 integration work
- capability handshake
- run lifecycle observation
- parent/child run representation when source supports it
- basic tool/resource/validation/artifact/outcome observation where source supports it
- idempotent event ingestion

### Protocol

- UARP v0.1 event envelope
- versioning
- stable IDs
- privacy flags
- evidence references
- high-volume aggregation strategy

### Semantic

- deterministic work-phase state machine
- basic domain classification across six domains
- Activity Mix
- semantic visibility/importance
- validation/recovery/delivery semantics
- no required external LLM

### Game Core

- Candidate Quest creation
- Run-to-Quest association
- Quest lifecycle

- Skill XP

### Persistence

- SQLite/local durable state
- world survives restart

### Presentation

## 3. Should-have if it does not threaten the vertical slice

- Chronicle/history
- manual Candidate Quest merge
- manual accept/continue/archive flow for Unverified result
- reduced-motion setting
- local diagnostics panel for adapter/event debugging
- Hall placeholder or first trophy prop

## 4. Explicit non-goals

Do not implement in v0.1:

### Game expansion

- equipment stats
- mounts
- real-money purchases, currency exchange and player trading
- job/class selection
- manual skill points
- random loot rarity economy
- random monsters
- complex combat
- navigable Dungeon
- full Campaign UI
- forced Dailies/streak punishment
- NPC AI
- social/guilds/PvP/leaderboards

### World simulation

- free character movement
- WASD/joystick
- pathfinding
- collision
- physics
- open world
- dynamic terrain generation
- procedural per-Quest maps
- large NPC simulation

### AI/control

- mandatory external LLM/API
- hidden-reasoning monitoring
- Game → Harness control
- workflow-modifying equipment
- strategy loadouts that change harness behavior
- public Control SDK

### Platform/ecosystem

- cloud account
- cloud sync
- multiplayer
- plugin marketplace
- public developer portal
- mature public Adapter SDK packaging/docs
- Surface SDK / IDE/TUI overlays

### Art burden

- unique art per Quest
- unique monster per error
- building art for every level
- generative AI art pipeline as a core dependency

## 5. v0.1 world content budget

Target a deliberately small world.

Required world objects:

- Small Camp
- AI Gate
- Quest Guild
- Workshop
- Library

Recommended visual states:

- Gate: Dormant / Connected / Active / Returning
- Guild: Old / Restored / Active / Return indicator
- Workshop: Locked / Idle / Active / Busy / Milestone
- Library: Locked / Idle / Active / Busy / Milestone

Maximum major visual tiers in v0.1: 1–2 per major building.

## 6. v0.1 reward budget

Reward families:

- Skill XP
- Domain Progress
- Artifact reference as Loot
- Milestone

Gold and cosmetic/companion unlocks are added under the accepted extension. Artifact-as-loot still requires a real evidence reference; a pet or shop purchase is a game inventory item, not a fabricated work artifact. Existing Skill XP and Domain Progress are not currency and are not spent in the shop.

## 7. v0.1 presentation budget

The first screen must remain world-centric.

Normal Return:

- 1–3 highlighted results
- 2–5 second sequence, skippable

Major milestone:

- stronger but still short world-change feedback

No persistent analytics dashboard on the world scene.

## 8. v0.1 data minimization

Default no full:

- prompt/conversation archive
- source code archive
- terminal transcript archive
- hidden reasoning
- secrets/env/credentials

Content access must be optional and scoped.

## 9. Scope-change rule

Any feature not listed under Must-have/Should-have is out of v0.1 until explicitly added to this document.

“Useful later” is not sufficient reason to implement it now.

When a future-facing abstraction is cheap and necessary to avoid a clear dead end, define the interface/extension point but do not build the future feature.
